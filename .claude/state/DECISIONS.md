# Decisions
One line per decision. Format: [YYYY-MM-DD] area: decision. Why: reason.
[2026-05-10] seed-pipeline: drop per-city `.ql` files; one config (`scripts/seed-cities.ts`) + templated Overpass query, bbox-based not admin-polygon. Why: admin polygons differ across countries (level 4/6/8) and don't represent multi-municipality regions like the GTA / SF Bay Area; bbox is uniform.
[2026-05-10] seed-mode: cafe-only filter is `amenity=cafe` + `shop=coffee|tea` only; ice_cream / internet_cafe / bakery / pastry excluded. Why: user wants cafés + cafe chains specifically — bakeries surface in Paris/Toronto + via user-submitted places elsewhere.
[2026-05-10] cafe-chains-as-fast-food: Tim Hortons / Dunkin' / Krispy Kreme are tagged `amenity=fast_food` in OSM and miss the cafe-only filter; reclassification deferred to #115 (post-seed brand-allowlist sweep) instead of widening the seed query. Why: re-running 19 city seeds is expensive; SQL pass over existing rows is cheaper and re-runnable.
[2026-05-05] places-lookup: chain Google → Foursquare → Photon, route detail by placeId prefix (`fsq:`/`osm:`). Why: free Foursquare key already in env covers POIs Photon (OSM) misses.
[2026-05-05] add-place: full-page wizard at `/places/new` instead of vaul drawer. Why: iOS keyboard squashes drawers; native page scroll is the only reliable mobile fix.
[2026-05-05] admin-access: keep `is_admin` flag, add belt-and-suspenders `ADMIN_EMAIL_ALLOWLIST` env (planned in #5). Why: defence-in-depth so a stray `is_admin=true` row can't grant access.
[2026-05-07] forms-drafts: persist add-place + review form state to localStorage instead of adding a separate "save & exit" nav button. Why: existing X already routes home; auto-save makes it lossless without new UI surface (issue #14 acceptance).
[2026-05-07] place-card: switch from fixed `h-[88dvh]` to vaul snap points `[0.55, 0.95]` (default 0.55). Why: iPhone SE (568pt) couldn't reach inlined Reviews; snap points give pull-up to ~95dvh without breaking desktop (FloatingPlaceCard renders ≥768px).
[2026-05-07] places-lookup: when FSQ search returns a Shopping Mall / Department Store hit, follow up with one Place Details call (cap 2 malls/query, 8 children/mall) to inline `related_places.children` as predictions. Why: mall-internal chains (Starbucks Beaugrenelle) don't surface as top-level FSQ hits; inline crawl fixes the live-search path without new UI.
[2026-05-07] review-photos: `next/image` with `remotePatterns` for `res.cloudinary.com`, no transform path — let Vercel's optimizer + Cloudinary's `f_auto/q_auto` defaults handle responsive delivery. Why: avoid double-optimizing or maintaining a custom Cloudinary loader for MVP.
[2026-05-07] map-pins: at zoom ≥18, displace colocated points in a 5m ring around the original centre via a hand-rolled helper (no turf). Why: 5m latitude-scaled offset doesn't justify pulling ~250kB of geodesy.
[2026-05-09] city-auto-switch: silent first-load switch replaced with a soft "We think you're in X — switch?" banner (#48) plus dismiss-by-city localStorage key. Why: silent override felt invasive for VPN / travel.
[2026-05-09] geolocate: Permissions API probe + cache last-known position + silent upgrade when granted; "denied" path opens a recovery modal not a toast. Why: iOS Safari sticky-deny made the geolocate button look broken with no visible failure.
[2026-05-09] welcome: precise-GPS prompt is user-initiated via a dedicated "Enable precise location" CTA on slide 3, never coupled to dismiss. Why: dismiss-coupled prompt fired too aggressively; users wanted the option to skip onboarding without surrendering location.
[2026-05-09] review-submit auth: 401 from /api/reviews flips a `needsLogin` state instead of redirecting; submit button transforms to "Sign in to post your review". Why: silent mid-submit redirect read like an auto-redirect; user wanted to read the message before leaving the page.
[2026-05-09] map default: filter store ships `categories = {'cafe'}` (non-persisted), `activeCount` ignores the new baseline, and a place outside the active set bypasses the category gate iff `has_user_reviews` is true (delivered) — refined to `category=='restaurant' && rating>=7.5` per user follow-up. Why: welcome state was drowned in fast-food + libraries; cafés-only with a high-bar restaurant override is the curated default.
[2026-05-09] cron security: dual-mode auth — `Authorization: Bearer CRON_SECRET` OR `x-vercel-cron: 1` header. Why: CRON_SECRET path supports human curl for ad-hoc runs; Vercel-only header covers the platform-scheduled invocations.
[2026-05-09] menus: image-only Cloudinary, `owner-menus/<placeId>/<asset>` folder, RLS keyed to `place_owners`. PDF support added later via `place_menus.file_kind`. Visibility toggle via `place_menus.visibility`. Why: reuse review-photos pipeline; PDF + visibility are small extensions.
[2026-05-09] orphan prune: daily cron walks `reviews/*` and `owner-menus/*` Cloudinary folders, deletes assets >24h old with no DB row, capped at 500 deletes/run. Why: DB rows can vanish independently of Cloudinary assets; orphans accumulate.
[2026-05-09] branch protection: main is now protected — PR required, `verify` status check required, force-push and deletion blocked, admins included. Why: solo dev safety net; matches the "main is protected" claim already in CLAUDE.md.
[2026-05-17] reviews #174: Imported segment in AllReviewsSheet is always visible with an empty/loading state, not hidden-when-zero. Why: hiding requires an upfront count request on every sheet open, which conflicts with the stronger "no extra request on the common path" requirement — lazy-on-first-switch wins.
